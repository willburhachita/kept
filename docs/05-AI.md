# AI (Claude) in Kept

Model: `claude-opus-5-5` (override with `AI_MODEL`). Every call goes through `backend/convex/ai/claude.ts`:
- **Structured outputs** with a JSON schema (`output_config.format`), then re-validated by deterministic code.
- **Server-side refusal fallback**: `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`).
- Typed error mapping; `refusal` and `max_tokens` stop reasons are handled before anything is parsed.

**Principle: the AI can only propose, or make the system more cautious. It never moves money on its own.**

## 1. Compiler (`compiler.ts`, `ai/prompts.ts`)

```
description ──► SPEC (promises, deadlines, deliverables, funding mode, assumptions, questions)
             ──► CLAUSES (rules written against the frozen spec)
             ──► verify()  ──fail──► REPAIR (rules only, up to 4 rounds, counterexamples as input)
             ──► applyTerms() ──► official server-side verification ──► review | needs_attention
```

- **Spec-first**: the promises are written before the rules, the way tests come before code. People read 2-4 promises, not JSON. The verifier connects the promises to the rules.
- **Frozen spec**: a repair that changes anything except the clauses (compared by canonical hash) is rejected, so the model cannot "fix" a counterexample by weakening a promise.
- **Live timeline**: every step (`spec`, `clauses`, `verify`, `repair`, `finish`) is appended to `compileRuns.steps`, with titles, details, violated property ids, the first counterexample and the bounds. Subscribe to `compiler.latestRun` to animate it.
- **Assumptions and questions** come back for both parties to read before approving.

## 2. Evidence examiner (`evidence.ts`, `ai/examiner.ts`)

- Input: the slot's agreed criteria (trusted), plus the submission (untrusted). Images go in as image blocks, PDFs as documents, SVG/text/JSON as text. Links cannot be opened, so the verdict is forced to `uncertain`. Images over 5 MB skip the model and go to a person.
- Output per criterion: `met`, `confidence`, `reason`; plus `overall`, `summary`, `suspectedManipulation`.
- Code enforces the decision: auto-accept only if `overall=pass`, every criterion is met, confidence is at or above the slot's `autoAcceptConfidence`, and no manipulation is suspected. Even then, acceptance only happens **after the challenge window**, and the funder can object (which sends it to arbitration). Anything else goes to the funder, then a dispute window, then an arbiter.

## 3. Spend screener (`agentApi.ts`, `ai/screener.ts`)

Runs only after the deterministic guard has approved a purchase. Fits plus low risk lets it proceed; anything else escalates to the owner. It can never approve something the guard denied.

## 4. Mandate drafter (`mandates.draftFromPrompt`)

Turns "let my agent spend up to $200 this week on office supplies…" into a policy, which is then validated and verified. Nothing is stored until the owner creates it.

## Prompt-injection defenses

- All user and third-party content is wrapped in `<untrusted source="…">` blocks, and the system prompt says it is data.
- Outputs are schema-constrained and re-validated; amounts and ids are checked by code.
- Decisions with money impact are gated by deterministic rules, time windows and humans.
- The examiner is told to flag any attempt to instruct it. Flagged submissions never auto-accept.
