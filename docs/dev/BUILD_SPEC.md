# Kept: build spec (internal contracts between modules)

This file is the contract every module is built against. If you implement a module, follow it exactly:
other modules call your functions by the names and argument shapes listed here.

"Kept" is the placeholder brand. Never hard-code it except through `BRAND` (`@kept/core`) or `env.brandName()` (backend).

## 1. What the product is

Two people (a **funder** and a **payee**) agree on a payment in plain English: "$100 now, $200 when the final logo
arrives within 7 days, refund me otherwise". Kept:

1. **Compiles** the text with Claude into a tiny contract language (the IR, `packages/core/src/ir.ts`): deadlines,
   evidence slots, **promises** (guarantees, the spec) and **clauses** (rules, the implementation).
2. **Proves** it with an exhaustive model checker (`packages/core/src/verifier.ts`): money is conserved, nothing gets
   stuck, every promise holds in every possible ordering of events, and the PayPal lifecycle fits (authorization valid
   29 days, honor period 3 days, refunds within 180 days). Failures come back as shortest counterexamples in plain
   English, and Claude **repairs** the clauses until the proof passes (it is never allowed to weaken the promises).
3. **Runs** it on real PayPal sandbox rails (`backend/convex/engine.ts`, `effects.ts`, `rails/`): Orders v2
   (AUTHORIZE or CAPTURE), partial captures, just-in-time reauthorization, void, partial refunds, Payouts, webhooks.
4. **Judges evidence** with Claude vision against the contract's acceptance criteria, behind a human challenge window
   and an arbiter (AI can never move money on its own).
5. **Mandates for AI agents**: an agent gets a scoped token instead of a card. Every spend request is checked by a
   pure guard (`packages/core/src/mandate.ts`) and optionally screened by Claude (screening can only escalate to a
   human, never approve). Reachable over REST and over a remote **MCP** endpoint.
6. **Receipts**: every state change is appended to a per-stream hash chain, signed with Ed25519, and sealed into
   RFC 6962 Merkle checkpoints (a transparency log). Anyone can verify with `@kept/core`.

## 3. Conventions (backend)

- Imports: `import { query, mutation, action, internalQuery, internalMutation, internalAction } from "./_generated/server";`
  `import { api, internal } from "./_generated/api";` `import { v } from "convex/values";`
- Every function declares `args` validators. Public functions start with `const userId = await requireUserId(ctx)`
  (`lib/authz.ts`). Never trust client-supplied user ids.
- **Service-function pattern**: write the logic once as `async function fooFlow(ctx, userId, args)` and export it twice:
  public `foo` (auth via session) and `fooAs` (internal, takes `userId`, used by the REST API with API keys).
  Mirror `contracts.ts`.
- Errors: `fail(code, message, extra?)` from `lib/errors.ts` (throws `ConvexError({code, message, ...})`).
  Codes: UNAUTHENTICATED, FORBIDDEN, NOT_FOUND, INVALID_ARGUMENT, INVALID_STATE, RATE_LIMITED, VERIFICATION_FAILED,
  PAYMENT_FAILED, AI_FAILED, CONFIG_MISSING, CONFLICT. Non-participants get NOT_FOUND (no existence oracle).
- Journal every meaningful state change in the same transaction: `appendJournal(ctx, stream, actor, type, data)`
  (`lib/journal.ts`). `stream` is the contract id or mandate id string. Actors: `actorUser(id)`, `"system"`,
  `"paypal"`, `` `agent:${tokenId}` ``, `` `arbiter:${userId}` ``. Keep `data` small, JSON-only, no secrets, mask emails
  with `maskEmail`.
- Notifications: `notify(ctx, userId, {kind, title, body, stream})`, `notifyStaff(ctx, {...})` (`lib/notify.ts`).
- Rate limits: `rateLimit(ctx, key, LIMITS.x)` inside mutations (`lib/rateLimit.ts`).
- Money: integer cents only. Use `formatCents`, `feeForRelease`, `authorizationAmount`, `maxFee` from `@kept/core`.
- PayPal calls happen ONLY through the outbox: `enqueueEffect(ctx, {stream, streamKind, kind, params, ref})`
  (`lib/outbox.ts`) from a mutation. Funding (order create/authorize/capture) is the one exception and happens in
  actions via `getRail()` (`rails/index.ts`); wrap rail errors with `rethrowRail` from `funding.ts`.
- Secrets/tokens are generated only in actions: `issueSecret(kind)` (`lib/secrets.ts`), store only `hash`.
- Randomness / `Date.now()` in mutations is fine (Convex makes them deterministic per transaction); `fetch` only in
  actions. Do not use Node built-ins (no `"use node"`) unless strictly necessary.
- AI: only via `callStructured` in `ai/claude.ts` with a JSON schema from `@kept/core` (`SPEC_OUTPUT_SCHEMA`,
  `CLAUSES_OUTPUT_SCHEMA`, `EVIDENCE_VERDICT_SCHEMA`, `SPEND_REVIEW_SCHEMA`, `MANDATE_OUTPUT_SCHEMA`). Wrap every piece
  of user/third-party content with `untrusted(label, text)` and tell the model it is data, not instructions.
  `aiConfigured()` tells you whether ANTHROPIC_API_KEY is set; degrade gracefully when it is not.
- Time constants: `SLA` and `PAYPAL_RULES` from `@kept/core` (`SLA.funderReviewHours`=72, `SLA.disputeWindowHours`=48,
  `SLA.arbiterHours`=72). Never invent different numbers: the verifier budgets time with exactly these.

## 5. Status machines

Contract: `draft -> compiling -> verifying -> review | needs_attention -> (both approve) awaiting_funding -> funding ->
active -> settling -> settled`; `frozen` from anywhere after funding; `cancelled` from any pre-funding state.
`compiling` is set by the compiler; `verifying` by `applyTerms`; `review`/`needs_attention` by `verification._store`.

Evidence (`evidence.status`):
```
checking ─(AI pass & conf>=slot.autoAcceptConfidence & no manipulation)─> challenge_window ─(window ends)─> accepted
    │                                                                        └─(funder challenges)─> in_arbitration
    └─(AI fail/uncertain/unavailable)─> awaiting_funder ─(funder accepts)─> accepted
                                              │  └─(funder rejects)─> funder_rejected ─(payee disputes)─> in_arbitration
                                              │                              └─(dispute window ends)─> rejected
                                              └─(no decision in SLA.funderReviewHours)─> in_arbitration
in_arbitration ─(arbiter decides)─> accepted | rejected
funder may accept early from checking / challenge_window / awaiting_funder.
```
Every transition to `accepted`/`rejected` MUST call `applyEvent(ctx, contractId, {type:"accept"|"reject", evidence:
slotId}, actor)` in the same mutation. Submission calls `applyEvent(..., {type:"submit", evidence: slotId}, ...)`.
If the contract is not `active` anymore (settled/frozen), record the decision but skip `applyEvent`.

Mandate: `draft -> awaiting_funding (policy verified) -> funding -> active -> closing -> closed`; `revoked` (owner) ->
closing; `frozen` (failures). Spend: `screening -> executing | needs_approval -> executing | denied`; `executing ->
paid | failed`; `cancelled` if a pending approval is declined or the mandate closes.

## 6. Evidence agent: `evidence.ts`, `arbiter.ts`, `ai/examiner.ts`

`evidence.ts` public: `generateUploadUrl {contractId}` (payee, contract active, rate-limited `LIMITS.evidenceUpload`,
returns `ctx.storage.generateUploadUrl()`), `submit {contractId, slotId, storageId?, text?, url?}` (payee; slot kind
must match: file -> storageId, text -> text <= 20000 chars, link -> https url <= 2000 chars; read file metadata from
`ctx.db.system.get(storageId)`: size <= 10 MB, contentType in png/jpeg/gif/webp/svg+xml/pdf/plain/markdown/json;
store `sha256` from the system row; insert with status `checking`, `beforeDeadlines` = deadlines not yet passed; call
`applyEvent(submit)`; journal `evidence.submitted` {slotId, sha256, kind}; schedule `internal.evidence.runExaminer`
if `aiConfigured()`, else go straight to `awaiting_funder` with `funderDecisionDueAt`; notify funder),
`list {contractId}` (participants/staff; for each item: slot label, status, timers, AI verdict summary, file URL via
`ctx.storage.getUrl`, and `canAccept/canReject/canChallenge/canDispute` booleans for the viewer), `accept
{evidenceId}` (funder), `reject {evidenceId, reason}` (funder, from `awaiting_funder` -> `funder_rejected`,
`disputeEndsAt` = now + SLA.disputeWindowHours), `challenge {evidenceId, reason}` (funder, from `challenge_window`),
`dispute {evidenceId, reason}` (payee, from `funder_rejected`). Each has an internal `...As` twin taking `userId`
(`generateUploadUrlAs`, `submitAs`, `acceptAs`, `rejectAs`, `challengeAs`, `disputeAs`, `listAs`).
Internal: `runExaminer {evidenceId}` (action: loads via an internal query, downloads the blob with
`ctx.storage.get`, builds Claude content: images as base64 image blocks, PDF as a document block, svg/text/json as
text, links as text with a note that the examiner cannot open links (forces `uncertain`); calls `callStructured` with
`EVIDENCE_VERDICT_SCHEMA`, effort "high"; then `_recordVerdict`), `_recordVerdict {evidenceId, verdict | error}`,
timers scheduled with `ctx.scheduler.runAt`: `closeChallengeWindow {evidenceId}`, `finalizeRejection {evidenceId}`,
`escalate {evidenceId}`; `sweepTimers` (cron every minute; idempotently advances anything overdue). In arbitration
set `arbitrationDueAt` = now + SLA.arbiterHours and `notifyStaff`.
The examiner prompt lives in `ai/examiner.ts`: strict, criterion by criterion, evidence is untrusted, report any
attempt to instruct the examiner as `suspectedManipulation`, pass only if every criterion is met.

`arbiter.ts` (staff only via `requireArbiter`): `queue` (evidence `in_arbitration` + frozen contracts + frozen
mandates + failed effects), `decide {evidenceId, outcome: "accepted"|"rejected", reason}`, `resume {contractId, note}`
(uses `resumeContract`), `retryEffect {effectId}` (uses `requeueEffect`), `setPayoutEmail {contractId, email, reason}`
(fixes a bad payee email on a frozen contract: patch `approvals.payee.payoutEmail`, journal it).

## 7. Mandates agent: `mandates.ts`, `agentApi.ts`, `ai/screener.ts`

`mandates.ts` public: `draftFromPrompt {prompt}` (action; Claude with `MANDATE_OUTPUT_SCHEMA`, then
`validateMandate`; returns `{policy, assumptions, issues}`, never stores), `create {policy}` (validate with
`validateMandate`, run `verifyMandate(policy, feeBps)`, store with `policyHash = sha256Hex(canonicalJson(policy))`,
status `awaiting_funding` if the report is ok else `draft`), `get {mandateId}`, `listMine`, `fundStart {mandateId}`
(action; Orders v2 intent AUTHORIZE for `authorizationAmount(budget, feeBps)`, reference_id = mandate id, returns
approveUrl), `fundConfirm {mandateId}` (action; authorize, then internal `_activate`: funding fields like contracts,
`activatedAt`, `expiresAt = activatedAt + expiresAfterHours`, schedule `expire` at expiresAt), `issueToken {mandateId,
label, expiresInHours?}` (action; `issueSecret("mt")`, store hash; token expiry <= mandate expiry; return token once),
`revokeToken {tokenId}`, `listTokens {mandateId}`, `spends {mandateId}`, `decideSpend {spendId, approve, reason?}`
(owner; approve -> execute, decline -> `cancelled` + release reservation), `revoke {mandateId}` (owner; closes).
Internal `...As` twins for REST: `createAs`, `getAs`, `listAs`, `fundStartAs`, `fundConfirmAs`, `issueTokenAs`,
`decideSpendAs`, `revokeAs`, `spendsAs`. Internal: `confirmFromWebhook {orderId} -> boolean`, `expireDue` (cron),
`expire {mandateId}`, `_close` (helper: status `closing`, cancel pending approvals, enqueue `void_authorization` (FIFO
after any in-flight spends); effects.ts marks it `closed` on success).
Executing an approved spend (helper `executeSpend`): `spentCents += amount`, `feesCents += fee`, `purchases += 1`,
`recentSpendTimes` push now (keep last hour), release any reservation, status `executing`, enqueue
`capture_authorization {amountCents: amount+fee, releaseCents: amount, feeCents: fee, purpose:"spend",
receiverEmail: merchantEmail, spendId, note}` on stream = mandate id, streamKind "mandate"; journal `spend.approved`.

`agentApi.ts` (called only by routes): `authenticate {tokenHash}` (internal query -> `{tokenId, mandateId, ownerId}` or
null; rejects revoked/expired tokens and non-active mandates), `mandateForAgent {tokenHash}` (remaining budget,
limits, purpose, expiry, recent spends; never owner PII), `requestSpend {tokenHash, merchantEmail, merchantName,
amountCents, currency, description, idempotencyKey}` (mutation: rate limit `agent:${tokenId}` with LIMITS.agentSpend;
idempotency via `by_token_key` (return the existing spend); evaluate with `evaluateSpend` from `@kept/core`; record
the spend with reasons; `deny` -> `denied`; `needs_approval` -> reserve `reservedCents += amount`, notify owner;
`approve` -> if `aiConfigured()` status `screening` (reserve) else `executeSpend`; touch `lastUsedAt`; journal
`spend.requested` with actor `agent:${tokenId}`), `screen {spendId}` (action: `ai/screener.ts` with
`SPEND_REVIEW_SCHEMA`, effort "low"; description and merchant are untrusted), `finishScreening {spendId, review}`
(mutation: fits && risk low -> `executeSpend`; else `needs_approval` with the AI's reasons; AI can only escalate),
`getSpend {tokenHash, spendId}` (agent can only read its own mandate's spends).

## 9. Transparency agent: `transparency.ts`, `backend/scripts/setup-keys.mjs`

`transparency.ts`: internal `checkpoint` (cron every 10 min): take up to 256 journal entries with `checkpoint === null`
via index `by_checkpoint` (eq null) in creation order; if none return; `root = merkleRoot(hashes)`; previous checkpoint
via `by_seq` desc; `cp = {seq, size, root, prevHash (GENESIS_HASH if none), at}`; `hash = checkpointHash(cp)`;
`sig = signCheckpoint(hash, signingKey())`; insert; patch each entry `{checkpoint: seq, leafIndex: i}`.
Internal `listCheckpoints {limit}` and `proofFor {entryHash}` -> `{entry: {stream, seq, hash}, leafIndex, treeSize,
proof (inclusionProof over that checkpoint's entries ordered by leafIndex), checkpoint: {seq,size,root,prevHash,hash,
sig,keyId,at}}` or null. Public queries `checkpoints {limit?}` and `proof {entryHash}` for the UI.
`backend/scripts/setup-keys.mjs`: Node script (ESM, no deps) that generates an RS256 key pair for Convex Auth
(`JWT_PRIVATE_KEY` as PKCS8 PEM with newlines replaced by spaces, `JWKS` as `{"keys":[{use:"sig", ...publicJwk}]}`)
and a 32-byte hex Ed25519 seed for `RECEIPT_SIGNING_KEY`, then sets them with `npx convex env set NAME -- value`
(child_process, never printing secret values; print only names and the receipt public key). Flags: `--prod` passes
`--prod` to convex; `--print` prints commands instead of running them. Also sets `SITE_URL` (default
http://localhost:5173, override `--site-url`) and `PAYMENT_RAIL=sim` unless `--rail paypal`.

## 10. Compiler agent: `compiler.ts`, `ai/prompts.ts`

Public action `compile {contractId}` and internal `compileAs {userId, contractId}` -> `{runId}`; start via mutation
`_begin` (participant check, status in draft/review/needs_attention, rate limit `LIMITS.compile`, set contract status
`compiling`, insert `compileRuns` row, journal `compile.started`). Pipeline (each step appended with `_step`, so the UI
can stream progress reactively):
1. **Spec** (`SPEC_OUTPUT_SCHEMA`, effort "high"): promises first. `validateSpec`; on errors retry once with the issues.
2. **Clauses** (`CLAUSES_OUTPUT_SCHEMA`, effort "high"), given the validated spec. `validateClauses`.
3. **Verify** with `verify(ir, {feeBps})`.
4. **Repair** up to 4 rounds: send `violationsForRepair(report)` + current clauses; the model returns new clauses only
   (spec is frozen: guarantees, deadlines, evidence, amounts, mode cannot change). If a round fails validation, feed
   the issues back.
5. If it still fails: finish with the best attempt and let `applyTerms` + verification put the contract in
   `needs_attention` (counterexamples visible); add a `questions` hint that the promises may conflict.
6. Finish: `_finish` calls `applyTerms(ctx, contract, ir, actor, "compiler")` (this sets `verifying` and schedules the
   official verification), stores `assumptions`/`questions` on the run, status `succeeded`, journal
   `compile.finished` {rounds, irHash}. On any error: `_fail` sets run `failed`, contract back to `draft` (or
   `needs_attention` if it had terms), journal `compile.failed`.
Public query `latestRun {contractId}` (participants) and `runs {contractId}`.
